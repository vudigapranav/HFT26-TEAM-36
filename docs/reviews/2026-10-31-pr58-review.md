## Incompatibilities that remain

1. **`src/backend/tests/generation/k8-wiring.test.ts`, "K8 connects the real generator and falls back on provider outage".**
   It injects `runTests` that throws ("Runner must not execute during provider fallback") and expects
   `generateAssessment` to return `ok` with three `seed_bank` tasks. On main, a fallback seed must still pass
   `validateTask`, which executes the reference against the independent oracle (`generation/generate.ts`: the check
   `checked.value.semantic_verified!==true` returns `unavailable`). With a throwing runner the result is `unavailable`,
   so the test fails. Fix: use a real Docker runner (skipIf no Docker) or a validation double that returns a full
   semantic certificate, and drop the "runner must not execute" assumption.
   Also `expect(modelCalls).toBe(2)`: under #63, the arrays-only families change which tiers have model calls;
   assert on behaviour (sources/family IDs), not a call count tied to the old registry.
2. **`src/backend/tests/persistence/persistence.integration.test.ts`, the new K8 three-set journey test.** Its injected
   `fallback` generator returns seed tasks directly; the journey only passes on main because the harness's
   `certifiedFixture` validation double (main, line 17) stamps `semantic_verified:true`. That proves persistence, not
   correctness. That's acceptable if the test is labelled as a persistence test with a certificate double. It also
   conflicts textually with main's version of the same file: both sides added tests at the end, so keep both.
3. **`docs/BACKEND_DECISIONS.md`, K8 section, now contradicts main:**
   - "K5 receipts do not claim an independent brute-force oracle or automatically validated statement semantics":
     main's receipts do claim an independent oracle (`differential` gate) and pinned contract/example agreement
     (`examples` gate). Delete or rewrite this.
   - "A provider failure returns compatible reviewed seeds": add "only after the same semantic verification".
   - "Master performance test IDs follow `/performance|perf|large_window/i`": performance is now per family
     (`performanceIds` in `generation/families.ts`); the regex note is obsolete.
4. **`docs/status/karthik.md`:** fine to keep as history, but any "K6 integrated" claim should cite #60 as the version on main.

## Suggested resolution

Rebase onto main. Keep wiring.ts (identical). Fix test 1. Keep test 2 with a clear "certificate double" label. Rewrite the
three doc lines. Then run `RUNNER=docker TORQUECODE_REQUIRE_DB=1 TORQUECODE_ALL_DB_TESTS=1 pnpm test:auth` with 0 skipped.
If the K8 tests add nothing beyond main's `tests/generation/generate.test.ts` and `tests/generation/arrays-families.test.ts`
(which already cover provider outage with real Docker), closing #58 is also reasonable.
